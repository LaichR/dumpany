## Commit messages

- Summarize what changed, not how it was implemented.
- Follow git conventions for formatting of commit messages
- Use one short, imperative subject.
- A body is only added if it provides additional explanation why a change was done.
- Do not list changed files, implementation steps, or testing performed.

## Documentation style

- Start with a short, self-contained statement describing what the item is used for.
- For items whose usage is not straightforward, briefly explain how to use them and common constraints. Prefer examples over detailed descriptions.
- Document each parameter.
- Describe the return value, including its meaning and relevant success or error conditions.
- Describe caller-visible behavior, not implementation details.
